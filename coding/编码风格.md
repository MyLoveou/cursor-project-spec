# 编码风格（通用）

> 来源：ECC [rules/common/coding-style.md](https://github.com/affaan-m/everything-claude-code/blob/main/rules/common/coding-style.md)  
> 适用：任意语言；语言特定规则见各 `backend/`、`frontend/` 文档

---

## 1. 不可变（Immutability）

**优先创建新对象，避免原地修改。**

- 前端：spread / 函数式更新 state
- 后端：DTO 用 record；集合返回新实例
- 好处：减少隐蔽副作用，便于调试与并发

---

## 2. 核心原则

| 原则 | 说明 |
|------|------|
| **KISS** | 用最简单能工作的方案； clarity > cleverness |
| **DRY** | 重复逻辑提取为工具/函数；避免复制粘贴漂移 |
| **YAGNI** | 不为假想需求建抽象；压力真实出现再重构 |

---

## 3. 文件与模块

| 规则 | 建议 |
|------|------|
| 倾向小文件 | 200–400 行常见；**800 行上限** |
| 高内聚低耦合 | 按功能/域组织，而非按技术类型堆目录 |
| 长函数 | 拆分为职责单一的小函数（**≤50 行** 为目标） |
| 嵌套 | 优先 early return；避免 **>4 层** 嵌套 |

---

## 4. 命名

| 类型 | 约定 |
|------|------|
| 变量、函数 | `camelCase`，语义清晰 |
| 布尔 | `is` / `has` / `should` / `can` 前缀 |
| 类型、组件、类 | `PascalCase` |
| 常量 | `UPPER_SNAKE_CASE` |
| Hook | `use` 前缀 |

---

## 5. 错误处理

- 每层**显式**处理错误，禁止静默吞掉
- UI 层：用户可读文案
- 服务端：记录足够上下文；**不**向客户端泄露栈/内部路径
- 边界（API、表单、文件）：校验后再处理

---

## 6. 输入校验

- 所有外部输入视为不可信（用户、第三方 API、文件）
- 使用 schema / Bean Validation 等在边界校验
- 快速失败 + 明确错误信息

---

## 7. 代码异味（避免）

- **魔法数字** → 命名常量
- **深层嵌套** → early return / 提取函数
- **巨型函数/文件** → 拆分
- **硬编码配置** → 环境变量或配置文件

---

## 8. 完成前自检

- [ ] 命名可读
- [ ] 函数短小、文件聚焦
- [ ] 无深层嵌套
- [ ] 错误已处理
- [ ] 无硬编码 secret/环境相关 magic value
- [ ] 最小 diff（不改动无关代码）
