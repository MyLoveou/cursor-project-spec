# 代码现状摸底（Codebase Inventory）

> **目标**：写技术方案前，用可复核证据描述「现在有什么」，而不是凭印象填表。  
> **硬事实**：一次 explore ≠ 摸底完成；空白单元格 ≠「各地相同」。

## 何时用

- 大需求 / SDD 写方案前
- 用户说「先梳代码」「现状摸底」「有哪些可复用」
- 域包 `*-codebase-map` 委托本 Skill 做通用流程

## 产出

写入约定路径（默认 `docs/design/features/<id>-codebase-map.md`，或域模板指定路径），且满足下方**证据与门禁**。

---

## 强制流程（四轮，不可合并成一轮聊天了事）

### 轮 0 · 范围锚定

1. 读已定稿/疑问表关闭后的需求要点（或 `requirements-gap`）
2. 列出**检索关键词清单**（功能名、渠道名、站点/国家、AB、表单字段、接口词）
3. 列出**对比轴**（至少：站点 × 国家/地区 × 渠道；按需求裁剪，但须显式写出「本需求不比什么」）

输出：`## 检索计划`（关键词 + 对比轴 + 计划 Grep/Glob 模式）

### 轮 1 · 入口与主路径（委派）

- Task `explore` **或** `@code-explorer`（只读）
- 要求产出：入口 → 调用链 → 关键文件表（路径 + 符号）
- 将结果贴进摸底文档「主路径」节，**保留文件路径**

### 轮 2 · 按对比轴差分（本轮最易漏，必做）

对每一对比轴组合（例：大陆 vs 香港）分别 Grep/读代码：

| 检查 | 不合格表现 |
|------|------------|
| API / client / URL / service 名 | 只写「认证接口」无路径 |
| 配置键 / 枚举 / if 站点分支 | 断言「一样」但无两侧证据 |
| 组件 / hook / 校验 | 只描述一侧 |

**规则**：若只找到一侧 → 另一侧必须写 `未找到（已搜：关键词…）`，**禁止**留空或默认「同左」。

### 轮 3 · 需求关键词覆盖

把轮 0 关键词逐条 Grep：

| 关键词 | 命中路径（可多条） | 与本需求关系 | 未命中时的结论 |
|--------|--------------------|--------------|----------------|
| | | 复用/扩展/新建/无关 | |

任一核心词「想当然有实现」但 Grep 无命中 → 标 **缺口**，不得写成已有能力。

### 轮 4 · 对抗复核（防自嗨）

换一轮提问（可新开子代理或自检清单）专门找漏：

- 「还有哪些站点/国家分支没打开文件？」
- 「回填/校验/AB/草稿是否只搜了中文或只搜了英文？」
- 「扩展点结论是否至少否定过 2 个候选路径？」

输出：`## 对抗复核`：仍存疑点列表；无则写「本轮未发现额外轴，残留风险：…」

---

## 证据标准（每条事实）

可接受：

- `path/to/File.ts` / `symbolName`（或行号区间）
- Grep 模式 + 至少一条命中路径
- 明确的 `未找到（已搜：…）`

不可接受：

- 「应该在某某模块」
- 「与现有逻辑类似」
- 空单元格、复制粘贴「同上」跨国家/站点

---

## 门禁（写技术方案前）

```text
PASS 仅当同时满足：
1. 摸底文档存在且含：检索计划、四轮痕迹、路径级证据
2. 对比轴每一侧有证据或「未找到（已搜）」
3. 需求关键词覆盖表无「假装已有」
4. §不确定项 列出所有猜测（不得藏在正文当事实）
5. 用户显式回复含「摸底已核实」或勾选文档「人工核实 = 已核实」
```

未 PASS → **STOP**，禁止 `plan-workflow` / 域 tech-design / 大范围实现。  
用户可要求「带风险继续」——须在方案文首记录**未核实条目**。

### AI 自检（提交摸底初稿时必须打印）

```markdown
【摸底自检】
- 检索计划：有 / 无
- 轮1 入口链：有 / 无
- 轮2 对比轴差分：有 / 无（轴：…）
- 轮3 关键词覆盖：有 / 无（未命中数：n）
- 轮4 对抗复核：有 / 无
- 空单元格当「相同」：是 / 否（必须为否）
- 请用户核实：是
```

自检任一项失败 → 先补摸底，不进入方案。

## 反模式

- 一轮对话填完整张表
- 用架构常识补全未打开的文件
- 把摸底写成实现方案
- 人未核实就写 HOW 方案
