## 4. 高频须问方向（开放发现的提示，非穷尽）

来自复盘痛点，具体结论入库 `business-rules` / `ui-interactions`：

| 方向 | 典型缺口 |
|------|----------|
| 回填字段与优先级 | 多来源谁赢；无值时留空还是拦截 |
| 站点 / 国家范围 | 是否仅大陆；香港等是否 in scope；API 是否分套 |
| 离开再进 | 是否重拉数据、与草稿/填写对比的时机 |
| AB | key、默认、未命中 |
| 拦截 | 时机、文案、可否跳过 |
| 改旧 vs 新增 | 是否有扩展点 |
| Figma/PRD 缺口 | 未标注却「好像评审提过」的项 |

## 5. 规范偏好（团队口头规范 · 复盘提及）

1. 奥卡姆剃刀：无必要，勿增实体  
2. 差异配置化 / 站点差异化要显式  
3. 变量体现业务  
4. 无实力不做大刀阔斧重构  

（具体落地仍以仓库规范与资深裁定为准。）
